# dialsched — 外呼名单调度库

单进程、串行调用的内存组件,在活动暂停、全局 DNC(拒接)标记与重试期限
共同作用下,从"活动 × 联系人"组合中挑选当前可拨的一项。不处理真实通话。
时间由调用方以整数秒传入,所有带时间的调用按时间单调不减执行。

## 接口

```go
s := dialsched.NewScheduler(contactIDs, campaignIDs, memberships)
s.SetCampaignState("C0", dialsched.Paused)   // Active <-> Paused
s.SetDoNotCall("c123", true)                 // 设置/解除全局 DNC
camp, cont, ticket, ok := s.Take(now)        // 领取一个可拨组合;ok=false 表示无候选
s.Finish(ticket, dialsched.NoAnswer, now)    // 结束拨号:Resolved / NoAnswer
```

- 初始化提供固定的联系人、活动及成员关系;活动最多 10 个,初始均为
  `Active`;每个组合初始可拨时刻为 0、尝试次数为 0。
- `Take` 成功即视为拨号开始:立即占用该联系人(跨所有活动唯一)并消耗
  一次尝试。返回所有合格组合中按 `(可拨时刻, 活动ID, 联系人ID)`
  字典序升序的首项。合格 = 活动 Active、联系人未 DNC 且未占用、组合未
  结束、可拨时刻 ≤ now。
- `Finish` 释放联系人:`Resolved` 或累计尝试达 3 次时组合永久结束;
  否则下次可拨时刻为 `now + 7200`。每张票据仅可提交一次。
- 暂停与 DNC 只影响后续领取,不撤销已开始的拨号;屏蔽期间可提交
  `Finish`,解除屏蔽后按原有可拨时刻与尝试次数恢复,预算不重置。
- 辅助接口:`Stats()` 报告常驻状态量,`ComboState()` 供测试核对。

## 实现与复杂度

两级堆结构(`scheduler.go` + `heap.go`):

- 每个活动一个**索引二叉堆**,驻留该活动内"组合未结束、未在拨、联系人
  未 DNC 且未占用"的全部组合,按 `(可拨时刻, 联系人ID)` 排序。堆中元素
  与活动是否暂停无关,因此暂停/恢复不触碰成员。
- 一个**全局堆**,只装各 Active 活动的堆首(每活动至多一项),按
  `(可拨时刻, 活动ID, 联系人ID)` 排序。
- 不变式:组合驻留在其活动堆中 ⟺ 未结束、未在拨、联系人未 DNC 且未占用。
  所有屏蔽/恢复都通过索引堆的 O(log) 精确删除/插入完成,无惰性残留项。

各操作代价(N = 成员关系数,U = 联系人数,k ≤ 10 为单联系人的成员关系数):

| 操作 | 时间 | 说明 |
|---|---|---|
| `SetCampaignState` | O(log N) 最坏 | 只在全局堆增/删/修一个活动条目,不遍历成员 |
| `SetDoNotCall` | O(k log N) | 对该联系人的 k 个组合各做一次堆删/插 |
| `Take` | O(k log N) 摊还 | 取全局堆首;占用联系人时摘除其 k 个组合。空领取只看堆首,接近 O(1) |
| `Finish` | O(k log N) 摊还 | 释放联系人后把其未结束组合逐一放回 |

空间:组合表 O(N)、每组合一个堆位置、全局堆 ≤ 10 项、在拨票据 ≤ U,
总计 O(N + U)。所有删除都是物理删除,状态量不随历史操作次数增长。

## 测试

```sh
go test ./...
```

- `scenario_test.go`:同一联系人属于两个活动,交错执行领取、暂停、DNC
  切换与失败提交再解除屏蔽,验证跨活动占用、原重试期限保留、第三次失败
  终止、时间恰好到期时的排序。
- `random_test.go`:20 组种子的小规模随机操作序列,与测试内每次全量扫描
  的独立参照器逐步比较 Take 结果与每个组合的尝试/结束状态。
- `stress_test.go`:10 万成员关系下,大量更早到期组合被暂停/DNC/占用,
  仅少量可拨;同一大活动与同一联系人 DNC 各切换 10 万次。实测(Apple
  Silicon):活动切换约 28 ns/次,DNC 切换约 179 ns/次,万次空领取约
  1.2 ms,耗尽约 10 万组合约 51 ms;切换前后 `Stats` 完全一致,证明候选
  不遗漏、取号不逐项穿过屏蔽前缀、状态不随切换次数膨胀。
